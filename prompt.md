Build a scrollytelling data visualization of land use in Flanders, modeled on Bloomberg's "2018 US land use" graphic (https://www.bloomberg.com/graphics/2018-us-land-use/). The region is rendered as a grid of equal-area square tiles shaped like a map of Flanders, each tile colored by land use class. As the user scrolls, the tiles animate out of the map layout and regroup into one waffle block per land use class, so the viewer can compare the relative size of each class.

Data source: the "lu_landgebruik_vlaa_2025_v3.tiff" dataset:. Report what you find and adapt the plan accordingly.

Stage 1, data pipeline (Python, in /pipeline). Aggregate the source data into square tiles in the projected CRS so every tile is equal-area. Make the tile size a single constant, default 2 km, and test 1 km as well. Drop edge tiles that are mostly outside Flanders. Group the many source classes into roughly 8 to 10 readable categories (for example built-up, cropland, grassland, forest, other nature, water, roads and infrastructure, industry and commercial) and put the mapping in a config file with Dutch labels and English labels. Assigning each tile its dominant class makes small classes vanish and large ones inflate, so after that, apply a largest-remainder correction: compute each class's true area share, convert it to a target tile count, and reassign the lowest-confidence tiles (those with the smallest dominant-class margin) until the per-class tile counts match the true shares. Output tiles.json with id, col, row and class per tile, plus stats.json with true area per class in km² and percent.

Stage 2, frontend (Vite + React + TypeScript + Tailwind, D3 for layout and scales). Render tiles as SVG rects, or canvas if the tile count makes SVG slow. Compute two positions per tile: its map position from (col, row), and its waffle position, where tiles are grouped by class and packed into a block per class, sorted by size with block positions laid out in a sensible arrangement. Each tile has a stable key and is animated between the two layouts with a staggered transition. Use Scrollama for scroll steps: an intro step with the map, then one step per class that highlights that class and dims the rest, then the regrouped waffle view with labels and percentages, and a closing step. Use a small gap between tiles for the Bloomberg look, a restrained palette that works for color-blind viewers, and a sticky graphic container with text cards scrolling over it. It must work well on mobile.

Quality bar: all totals shown in the UI must come from stats.json, not hardcoded.
